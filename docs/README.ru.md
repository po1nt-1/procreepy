# procreepy

Небольшая кроссплатформенная утилита (Linux, Windows, macOS): извлекает из
`.procreate` готовый архивный таймлапс и собирает его сегменты в один MP4.
Ничего не перекодирует (stream copy) и ничего не рендерит.

`.procreate` — это ZIP-архив. Если запись таймлапса была включена, внутри
находятся

```text
video/segments/segment-1.mp4
video/segments/segment-2.mp4
...
```
Утилита берёт именно эти файлы, сортирует их **численно** (`segment-9` раньше
`segment-10`), разбирает структуру MP4 каждого сегмента и пересобирает их в
один moov-first MP4, копируя кадры как есть. В пакетном режиме для каждой
обработанной работы она дополнительно пишет пересобираемую копию проекта без
таймлапса, а с флагом `--psd` — PSD-документ Photoshop со слоями. Путь
таймлапса вообще не открывает `Document.archive`, слои и растровые чанки
(`*.lz4`) — только `--psd`.

## Требования

Внешние зависимости не нужны: ни `ffmpeg`, ни `ffprobe`. Для сборки нужны только Go (версия указана в `go.mod`) и `make` (есть на всех поддерживаемых платформах; в минимальных системах устанавливается через менеджер пакетов).
Makefile — каноническая точка входа для сборки: он фиксирует ту же герметичную среду, которую использует CI (офлайн-режим для модулей, локальный toolchain, без cgo), и сам находит Go toolchain.

```bash
make build      # собрать всё и получить запускаемый ./procreepy
make check      # gofmt + сборка + vet + полный набор тестов
```

`make build` встраивает в бинарник `dev-<short sha>` (вне git checkout — `dev-nogit`), поэтому `procreepy --version` показывает, откуда он собран (в release-tarball вместо этого записывается тег). Без `make` прямой эквивалент — `go build ./... && go build -o procreepy ./cmd/procreepy` (такой бинарник сообщает `dev`, либо `dev-<commit>`, если доступен VCS-stamping).

### Сборка под другие ОС

Проект написан на чистом Go и без проблем кросс-компилируется под все поддерживаемые цели. С любой платформы:

| Цель | Команда |
|---|---|
| Linux x86-64 | `make release GOOS=linux GOARCH=amd64` |
| Linux ARM 64-bit (Raspberry Pi, Graviton) | `make release GOOS=linux GOARCH=arm64` |
| Linux ARM 32-bit | `make release GOOS=linux GOARCH=arm` |
| Windows x86-64 (10/11) | `make release GOOS=windows GOARCH=amd64` |
| Windows ARM 64-bit | `make release GOOS=windows GOARCH=arm64` |
| macOS Intel | `make release GOOS=darwin GOARCH=amd64` |
| macOS Apple Silicon (M1–M5) | `make release GOOS=darwin GOARCH=arm64` |
Каждая цель создаёт нормализованный `dist/procreepy-<version>-<os>-<arch>.tar.gz` и выводит его SHA-256; `make cross` собирает всю матрицу сразу, а `make repro` доказывает побитовую воспроизводимость сборки. Прямой эквивалент одной цели — `GOOS=… GOARCH=… go build -o procreepy[.exe] ./cmd/procreepy`.
Все сборки статические (без cgo): Linux-бинарник работает в любом дистрибутиве независимо от версии glibc. CI-конвейеры (GitLab и GitHub) собирают ровно эти цели при каждом коммите и, поскольку Windows — основная платформа, дополнительно прогоняют весь набор тестов нативно под Windows; задача `dist` публикует tarball-ы вместе с манифестом `SHA256SUMS`, а задачи `repro:*` подтверждают побитовую воспроизводимость бинарников.

- Linux/macOS: устанавливать ничего не нужно, просто запустите бинарник.
- Windows: бинарник не подписан, поэтому SmartScreen может показать «Защита вашего ПК» — выберите **Подробнее → Выполнить в любом случае**.

## Использование

Один файл:

```bash
procreepy artwork.procreate artwork.mp4
procreepy artwork.procreate > artwork.mp4
cat artwork.procreate | procreepy - > artwork.mp4
procreepy --list artwork.procreate
procreepy --verify artwork.procreate
```
Поддерживаются все четыре комбинации `INPUT`/`OUTPUT`:
`FILE OUTPUT`, `FILE -`, `- OUTPUT`, `- -`. Если `OUTPUT` не указан, используется
stdout. Если `OUTPUT` — существующий каталог, видео помещается туда под
исходным именем (`procreepy art.procreate videos/` → `videos/art.mp4`).

### Пакетный режим: папка с `.procreate` → папки с видео и проектами

Сценарий: в `input/` лежит много `.procreate`, а результаты нужны в
`output/`:

```bash
procreepy input/
```

Каждая обработанная работа даёт пару — таймлапс и пересобираемый проект без него:

```text
input/                               output/
├── Portrait of a Cat.procreate  →   ├── timelapses/Portrait of a Cat.mp4
│                                    ├── projects/Portrait of a Cat.procreepy.procreate
├── Landscape v2.procreate       →   ├── timelapses/Landscape v2.mp4
│                                    └── projects/Landscape v2.procreepy.procreate
└── No Timelapse.procreate              (пропущена с предупреждением — ничего не написано)
```
- **Имена**: `<имя оригинала без .procreate>`, плюс `.mp4` или
  `.procreepy.procreate`. Пробелы, кириллица и специальные символы сохраняются
  как есть; на файловой системе, не различающей регистр, имена, отличающиеся
  только регистром букв, получают суффиксы `-2`, `-3`, …
- **Папка результата**: по умолчанию `output/` относительно текущего
  каталога, создаётся автоматически. Другую можно указать вторым аргументом:
  `procreepy input/ ~/Videos/procreate`.
- **Облегчённый проект**: `projects/NAME.procreepy.procreate` — тот же архив
  без элементов `video/segments/segment-N.mp4`; все остальные члены переносятся
  байт в байт (порядок, методы сжатия, метки времени). Проект сохраняет время
  изменения исходного файла, поэтому повторный импорт в Procreate не
  перемешивает галерею.
- **Повторный запуск безопасен**: файл, чьи таймлапс и проект уже существуют,
  пропускается; недоделанная пара пересобирается целиком. Чтобы пересобрать
  всё: `--force` (`-f`).
- **`-r`** также заходит в подпапки; их структура повторяется в обоих
  деревьях, поэтому одинаковые имена в разных каталогах не конфликтуют.
- **Один повреждённый файл не останавливает остальные.** Файл без таймлапса
  (запись была отключена) — это предупреждение, а не ошибка: для него ничего
  не пишется. Повреждённый файл — ошибка: он попадает в итоговую сводку, а
  код выхода становится `1`.
- **Атомарные наборы**: результаты одного файла (таймлапс + проект, а с
  `--psd` ещё и PSD) пишутся во временные файлы и публикуются целиком — либо
  все, либо ничего. Неудачный запуск никогда не оставляет осиротевшее видео
  рядом с несуществующим проектом.
- Скрытые файлы (`._Foo.procreate`, которые macOS оставляет при копировании)
  игнорируются.
- Исходные файлы никогда не изменяются.

Пример вывода (всё это — в stderr; запуск завершается с кодом `1` из-за
повреждённого файла):

```text
level=INFO msg="batch conversion started" files=4 input=input/ timelapses=output/timelapses/ projects=output/projects/
level=ERROR msg="file conversion failed" input="input/Corrupt file.procreate" err="input is not a valid ZIP archive: input/Corrupt file.procreate (not a .procreate file, or truncated/corrupted)"
level=INFO msg=converted input="input/Landscape v2.procreate" timelapse="output/timelapses/Landscape v2.mp4" project="output/projects/Landscape v2.procreepy.procreate" removed_segments=17 video_size="6.7 MiB"
level=WARN msg="no timelapse video inside, skipped" input="input/No Timelapse.procreate"
level=INFO msg=converted input="input/Portrait of a Cat.procreate" timelapse="output/timelapses/Portrait of a Cat.mp4" project="output/projects/Portrait of a Cat.procreepy.procreate" removed_segments=18 video_size="4.1 MiB"
level=INFO msg="batch completed" converted=2 existed=0 no_video=1 failed=1
```

`removed_segments` — число файлов сегментов, исключённых из облегчённого
проекта, а `video_size` — их общий (сжатый) размер в архиве. Повторный запуск
той же команды сообщает для каждой существующей пары:

```text
level=INFO msg="skipped, outputs already exist (use --force to overwrite)" input="input/Landscape v2.procreate" timelapse="output/timelapses/Landscape v2.mp4" project="output/projects/Landscape v2.procreepy.procreate"
```

`--list` и `--verify` тоже принимают каталог и проходят по всем файлам в нём.

### Экспорт PSD (`--psd`)

```bash
procreepy --psd input/ out/
```

Только входной каталог. Рядом с каждой парой пишется `out/psd/NAME.psd`,
публикуется атомарно вместе со всем остальным набором:

```text
level=INFO msg="psd exported" input="input/Portrait of a Cat.procreate" psd="out-psd/psd/Portrait of a Cat.psd" layers=3
```

Что попадает в PSD:

- дерево слоёв (группы, порядок), имена слоёв (Unicode), видимость,
  непрозрачность, режимы наложения, границы и состояние блокировок;
- пиксели 8-битного RGBA для каждого слоя (сжаты PackBits);
- DPI и встроенный ICC-профиль;
- объединённый композит, взятый как есть из собственного flatten-рендера
  Procreate (если его нет или он повреждён, видимые слои складываются в
  режиме Normal как приближение).

Чего там нет — PSD это экспорт, а не безпотерьный обратный переход:

- маски слоёв и точная семантика клиппинга к слою снизу не сохраняются;
- у текстовых слоёв остаются пиксели, но не редактируемые данные текста;
- непрямое (преумноженное) alpha не восстанавливается точно: Procreate хранит
  преумноженные 8-битные плитки, поэтому цвета каймы по краям слоёв могут
  слегка отличаться;
- холсты шире или выше 30000 пикселей отклоняются outright (ограничение
  формата PSD, а не PSB).

`.procreate` остаётся мастер-копией; PSD — это снимок для Photoshop и других
импортёров.

### Диагностика

```bash
procreepy --list artwork.procreate
```

```text
input: input/Portrait of a Cat.procreate
segments: 18

1  video/segments/segment-1.mp4
2  video/segments/segment-2.mp4
3  video/segments/segment-3.mp4
...
17 video/segments/segment-17.mp4
18 video/segments/segment-18.mp4
```

```bash
procreepy --verify artwork.procreate
```
Каждый сегмент разбирается прямо из архива (включая проверку CRC внутри ZIP),
выводится построчный отчёт и проверяется, что сегменты можно объединить без
перекодирования. **Выходной файл видео не создаётся.** `--list` читает только
каталог ZIP.

## Опции

| Опция | Что делает |
|---|---|
| `-h`, `--help` | показать справку и выйти |
| `--list` | вывести сегменты в порядке воспроизведения и выйти |
| `--verify` | проверить каждый сегмент; выходное видео не создавать |
| `-r`, `--recursive` | входной каталог: также обходить подпапки |
| `-f`, `--force` | входной каталог: перезаписывать уже существующие результаты |
| `--strict` | считать пропущенные номера сегментов ошибкой (по умолчанию предупреждение) |
| `--psd` | входной каталог: дополнительно экспортировать PSD со слоями для каждой работы |
| `--tmpdir DIR` | куда помещать временные файлы (по умолчанию: `$TMPDIR`, затем `/var/tmp`, затем системный каталог) |
| `-q`, `--quiet` | выводить только предупреждения и ошибки |
| `--version` | показать версию и выйти |
| `--` | остановить разбор опций; остальное — позиционные аргументы |

## Как это работает

1. `INPUT` — файл или stdin. Stdin (и любой ввод без произвольного доступа)
   сначала сохраняется во временный файл, потому что ZIP требует произвольного
   доступа.
2. ZIP проверяется в режиме только для чтения, после чего находятся записи
   `video/segments/segment-N.mp4`.
3. Численная сортировка. Пропуски в нумерации — предупреждение; имена без
   номера игнорируются с предупреждением.
4. Каждый сегмент разбирается прямо из ZIP (без полного извлечения): MP4-боксы,
   размеры дорожек, параметры кодека. При первой ошибке работа останавливается.
5. Проверка совместимости (разрешение, кодек, наборы SPS/PPS, аудио). Иначе
   `-c copy` мог бы молча создать некорректные данные — поэтому несовместимость
   считается ошибкой с понятным сообщением, а не сюрпризом в готовом видео.
6. Собирается moov-first MP4: `ftyp`, `moov` (все дорожки, вырезанные из
   сегментов), затем `mdat` за `mdat` в порядке воспроизведения.
7. Всё, что обещает запуск (MP4, облегчённый проект, PSD), складывается во
   временные файлы и публикуется единым набором только после успеха последнего;
   в пакетном режиме независимо от этого берётся следующий вход.
8. Временный файл (если он создавался) всегда удаляется — при успехе, ошибке,
   Ctrl+C и SIGTERM.

### Запись в файл и в stdout

В обоих случаях собирается одинаковый moov-first MP4: атом moov записывается
первым, потому что кадры копируются непосредственно из исходных сегментов, а
метаданные известны до начала записи. Для файла это «классический» MP4,
подходящий и для плееров, и для редакторов; в pipe уходит абсолютно тот же
файл — `> artwork.mp4` даёт тот же результат, что и явный
`procreepy artwork.procreate artwork.mp4`.
  * **Вывод в файл** атомарен: рядом с целью создаётся `.partial`, которое
    переименовывается только после успеха. Неудачный запуск не оставляет
    обрезанных файлов и не повреждает существующий файл.
  * Специфика Windows: финальный rename выполняется `MoveFileEx` с заменой
    существующего файла, поэтому `--force` и регенерация неполного набора
    заменяют готовые файлы на месте — так же, как на Unix. Он не строго
    атомен, как POSIX rename; практически разница проявляется лишь в одном
    случае — если целевой файл всё ещё открыт в другой программе (например,
    медиаплеер держит предыдущий MP4), замена отклоняется с читаемой ошибкой
    `Access is denied`, старый файл остаётся нетронутым, и повторный запуск
    после закрытия программы завершается успешно.
  * stdout никогда не засоряется текстом. Все строки журналирования
    (`level=INFO`/`WARN`/`ERROR`, одна структурированная запись key=value на строку)
    идут в stderr. Единственное исключение — отчёт `--list`/`--verify`, где
    stdout является результатом. Если stdout — терминал, утилита отказывается
    выводить в него двоичный MP4.

### Цвета в консоли

Когда stderr — интерактивный терминал и переменная окружения `NO_COLOR` не
задана, токены уровней `WARN` и `ERROR` подсвечиваются (жёлтым и жирным
красным); `INFO` остаётся обычным. Пайпы, редиректы, CI и тесты сохраняют
побайтовый «обычный» формат, поэтому на скрипты ничего не влияет. Флага
`--color` намеренно нет.

### Временные файлы и Fedora

В Fedora `/tmp` — это tmpfs в оперативной памяти. Сегменты таймлапса могут
занимать сотни мегабайт, а при чтении из stdin весь `.procreate` сохраняется
во временный файл. Поэтому временный каталог выбирается так:
`--tmpdir` → `$TMPDIR` → `/var/tmp` (на диске) → системный каталог. Если при
сохранении закончится место на диске, будет выдано понятное сообщение с
подсказкой (использовать `--tmpdir` в более вместительном каталоге на диске),
а не просто «No space left».

## Коды выхода

| Код | Значение |
|---|---|
| 0 | успех |
| 1 | непредвиденная ошибка; в пакетном режиме — хотя бы один файл завершился с ошибкой |
| 2 | неверные аргументы (включая `--psd` с одиночным файлом или вывод целого набора результатов в stdout); `OUTPUT` совпадает с `INPUT`; stdout — терминал |
| 3 | вход не найден, пуст или не является ZIP |
| 4 | в архиве нет `video/segments` (таймлапс не записывался) |
| 5 | повреждённый сегмент; неоднозначная или отсутствующая нумерация (`--strict`) |
| 6 | зарезервирован (не используется: внешних зависимостей нет) |
| 7 | сегменты несовместимы для stream copy |
| 8 | зарезервирован (не используется: внешних зависимостей нет) |
| 9 | не удалось записать результат или временные файлы |
| 130 | прервано (Ctrl+C / SIGTERM) |

## Тесты

```bash
make test          # or: go test ./...
```
Настоящие `.procreate` не нужны: тесты собирают ZIP из сгенерированных
MP4-сегментов (см. `internal/testkit`). Проверки структурные: разбор
полученного MP4, порядок боксов, число сэмплов, содержимое `mdat`.
`-race` не требуется, но работает при установленном компиляторе C.
Покрыты: обычный файл, отсутствие `video/segments`, один сегмент, сегменты
в неправильном порядке (`segment-9`/`segment-10`), stdin, stdout, пробелы и
специальные символы в именах, повреждённые и обрезанные ZIP, повреждённые и
обрезанные MP4, повреждение CRC, ошибки записи (`/dev/full`), несовместимые
сегменты и весь пакетный режим.

## Чего утилита намеренно не делает

Путь таймлапса не разбирает `Document.archive` (NSKeyedArchive), не трогает
`*.lz4`, не восстанавливает слои и не рендерит изображение; `--psd` документ
разбирает — для описанного выше экспорта, с оговорками точности из того же
раздела. Если таймлапс не записывался, эта утилита не может восстановить его
из истории рисования. Замечание: `lz4 -t` для `.lz4`, извлечённого из
`.procreate`, не является проверкой целостности — это не самостоятельные
LZ4-фреймы.
